# 깃 협업 규칙

## Branch

<table>
<tr>
<td width="33%" valign="top">

#### main

```
최종 브랜치
```

- 주간 1회 `develop → main` PR만 진행
- **PM이 주간 종합해서 올림**

</td>
<td width="33%" valign="top">

#### develop

```
개발 메인 브랜치
```

- 개인 티켓 작업 후 develop 브랜치로 PR 진행
- **같은 파트 팀원**이 검토 후 머지
  (Front↔Front, Back↔Back, AI↔AI)

</td>
<td width="34%" valign="top">

#### 개인 작업 브랜치

```
PROMPT-{티켓번호}-{파트}-{설명}
```

- **Jira에서 자동 생성하여 사용!!**
  직접 만들 필요 없음!

</td>
</tr>
</table>

> 현재 Jira 자동 생성 브랜치 이름에서 한글이 브랜치 이름에 있으면 인코딩 문제가 간혹 발생하는데 추후 대안 모색

## Commit

<table>
<tr>
<td width="50%" valign="top">

#### 작업 태그

| Tag | 용도 |
|---|---|
| `init` | 프로젝트/모듈 최초 생성 |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `add` | 새 파일(이미지, 문서 등) 추가 |
| `design` | 디자인 추가/수정 |
| `docs` | 문서(README, `docs/` 등) 수정 |
| `chore` | 빌드 설정, 의존성, Docker 등 |
| `style` | 코드 포매팅, 들여쓰기 등 |
| `refactor` | 리팩토링 |
| `test` | 테스트 코드 추가/수정 |
| `rename` | 파일/폴더 이름 변경 |
| `remove` | 파일/폴더 삭제 |

</td>
<td width="50%" valign="top">

#### 커밋 메시지 형식

```
[개발 파트] <작업 태그>: 작업 내용
```

- 개발 파트는 `Front`/`Back`/`AI`(Jira 티켓 표기와 통일)
- 작업 태그는 **영어 소문자**
- 작업 내용은 한글로 간결히.

**예시**

```
[Back] feat: 매장 목록 조회 API 추가
[Back] fix: 사업자등록번호 검증 로직 버그 수정
[Back] test: StoreService 단위 테스트 추가
```

- ⭐️**한 커밋 = 의미 있는 변경 하나.** 
- `git add .`로 비빔밥 커밋 하지 않기!
- 관련 있는 파일들만 골라서(`git add <file>`) 커밋.

</td>
</tr>
</table>

## Pull Request

<table>
<tr>
<td width="50%" valign="top">

#### 개인 PR (`개인 작업 브랜치 → develop`)

- **리뷰어**: 같은 파트 팀원 <- Reviewers에 추가!!
- `.github/pull_request_template.md`에 있는 필요 내용들을 간단히 작성
- **상세 구현 내용은 Notion에 기록**

</td>
<td width="50%" valign="top">

#### 종합 PR (`develop → main`)

- **PM이** 그 주 `develop`에 머지된 내용을 종합해서 main에 PR
- PR 내용은 템플릿에 따라 작성
- **base가 `main`인지 확인!!**

</td>
</tr>
</table>

#### PR 제목

```
[파트] 제목
```

**예시**: `[Back] 컨벤션 문서화`
