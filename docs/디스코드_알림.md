# 디스코드 알림

팀 채널로 가는 PR 알림이 **언제 울리고 누구를 부르는지** 적어 둡니다.
"왜 나를 불렀지" 싶을 때 여기를 보세요.

보내는 곳은 전부 팀 전용 웹훅 하나(`DISCORD_WEBHOOK_TEAM`)입니다.
운영진 공용 `DISCORD_WEBHOOK` 은 쓰지 않습니다 — 이유는 아래 [웹훅](#웹훅) 참고.

## 1. PR 이벤트가 생기는 즉시

`.github/workflows/notify-discord-team.yml` → `.github/scripts/pr_event_notify.py`

| 언제 | 문구 | 누구를 멘션 |
|---|---|---|
| `develop` PR 이 올라옴 (리뷰어 지정됨) | 🔵 새 PR 이 올라왔습니다 (→ develop) | 지정된 리뷰어 전원 |
| `develop` PR 이 올라옴 (리뷰어 없음) | 🔵 + ⚠️ 리뷰어가 지정되지 않았습니다 | 작성자 |
| 올린 뒤 리뷰어를 바꾸거나 추가 | 👀 리뷰어로 지정되셨습니다 | 새로 지정된 리뷰어 |
| 리뷰가 달림 (승인) | 🟢 승인됐습니다 | PR 작성자 |
| 리뷰가 달림 (변경 요청) | 🔴 변경 요청이 왔습니다 | PR 작성자 |
| 리뷰가 달림 (코멘트) | 💬 리뷰 코멘트가 달렸습니다 | PR 작성자 |
| **멘토 PR(`main`)에 리뷰가 달림** | 🧑‍🏫 멘토 PR 에 리뷰가 달렸습니다 | PR 작성자 + 테크리더 전원 |
| **팀원이 아닌 사람이 PR 에 코멘트** | 🧑‍🏫 멘토 코멘트가 달렸습니다 | PR 작성자 + 테크리더 전원 |
| **멘토 되물음** (코드 코멘트 **답글**) | 🧑‍🏫 멘토 코멘트가 달렸습니다 | PR 작성자 + 테크리더 전원 |
| 팀원이 PR 에 코멘트 | 💬 코멘트가 달렸습니다 | PR 작성자 |
| `develop` 에 머지됨 | ✅ develop 에 머지됐습니다 | 없음 |

알리지 **않는** 것

- 초안(draft) PR
- 머지 없이 그냥 닫은 PR (소음)
- 리뷰어에서 **빠진** 경우 — 안 봐도 되는 사람을 부르는 건 소음이라 조용히 지나갑니다
- 자기 PR 에 자기가 단 리뷰·코멘트
- **새로 다는 인라인 코멘트** — 리뷰 제출이 한 번에 묶어 알립니다. 여기까지 전부 알리면
  리뷰 한 번에 열 번이 울립니다. 그래서 코드 코멘트는 **답글(되물음)만** 봅니다
- 진짜 이슈(PR 아님)에 달린 코멘트

> **멘토 리뷰는 시각으로 보지 않습니다.** 언제 올지 정해져 있지 않고 재촉할 일도
> 아니라서, cron 으로 "왔나?" 를 확인하지 않고 **멘토가 코멘트를 남기는 순간** 알립니다.
> 매핑(`DISCORD_MEMBERS`)에 없는 사람을 "팀원이 아닌 사람"으로 봅니다.
> 8주차에 멘토 되물음 2건을 다음 주까지 못 보고 넘긴 적이 있어 넣었습니다.

> **같은 PR 이 두 번 울리지 않게** — 리뷰어까지 지정해서 PR 을 올리면 GitHub 은
> `opened` 와 `review_requested` 를 둘 다 보냅니다. 올라온 지 2분 안쪽의
> `review_requested` 는 `opened` 가 이미 멘션했으므로 건너뜁니다.

## 2. 매시 정각 점검

`.github/workflows/remind-discord-team.yml` → `.github/scripts/remind_discord.py`

서버 없이 GitHub Actions 의 cron 으로만 돕니다. 판단은 스크립트가 KST 로 환산해서 합니다.

| 조건 | 문구 | 누구를 멘션 |
|---|---|---|
| **리뷰어 미지정**으로 2시간 경과 | 🔴 리뷰어가 아직 정해지지 않았습니다 | 작성자 + **테크리더** |
| 리뷰어는 있는데 리뷰 0건 · 1시간 | 🕐 아직 리뷰가 없습니다 | 리뷰어 |
| 리뷰어는 있는데 리뷰 0건 · 4시간 | 🟠 4시간째 리뷰가 없습니다 | 리뷰어 + 작성자 |
| 승인됐는데 6시간 넘게 미머지 | 🟢 승인됐는데 아직 머지되지 않았습니다 | 작성자 |
| 매일 10:00 · 충돌난 PR | ⚔️ 충돌이 나 머지할 수 없는 PR 이 있습니다 | 작성자 |

> **두 갈래로 나눈 이유** — PR 이 막히는 방식이 둘입니다.
>
> *리뷰어가 아예 없는 PR* 은 **아무의 일도 아닌 상태**라 그냥 두면 영영 안 봅니다.
> 리뷰를 독촉해도 부를 사람이 없으니, "정해 달라"고 작성자와 테크리더를 부릅니다.
>
> *리뷰어는 있는데 안 보는 PR* 은 부를 사람이 분명합니다. 1시간째에 리뷰어만 가볍게,
> 4시간째에 작성자까지 한 번 더. 거기서 끝냅니다 — 계속 울려봐야 소음입니다.
>
> 코드 리뷰 가이드의 팀 규칙은 *"리뷰 기한은 PR 작성 후 24시간 이내"* 인데, 24시간에
> 처음 알리면 그때가 이미 기한이라 늦습니다. 그래서 훨씬 앞으로 당겼습니다.

> **조용한 시간 (00:00~08:00 KST)** — 1시간 독촉을 넣으면서 새벽에 멘션이 가는 일이
> 생겨서, 이 사이에 임계값을 넘긴 건은 울리지 않고 **08:00 에 모아서 한 번** 보냅니다.
> 여러 건이 몰려도 한 메시지로 묶입니다.

> **매시간 똑같은 걸 다시 알리지 않는 방법** — "임계값을 넘겼다"가 아니라
> "**이번 한 시간 안에** 넘겼다"로 조건을 좁힙니다. 매시간 도니까 각 PR 은 그 구간을
> 정확히 한 번만 지나갑니다. 상태를 저장할 곳이 없어도 중복이 안 생깁니다.
>
> 충돌은 "언제 깨졌는지" 타임스탬프가 없어 이 방법을 못 씁니다. 그래서 하루 한 번
> 고정 시각에만 봅니다. GitHub 이 아직 충돌 여부를 계산하지 않았으면(`mergeable: null`)
> 그날은 넘어가고 다음 날 다시 봅니다.

## 3. 멘토 리뷰 사이클

`_local/코드 리뷰 가이드.md` 의 일정을 그대로 따릅니다.

| 시각 (KST) | 가이드상 | 알림 | 멘션 |
|---|---|---|---|
| 수 15:00 | — | ⏰ 3시간 뒤 1차 PR 마감 (main PR 이 없을 때만) | 없음 |
| **수 17:00** | 수 18:00 팀장 1차 PR | ⏰ 1시간 뒤 1차 PR 마감 | 테크리더 |
| 토 08:00 | — | ⏰ 2시간 뒤 재리뷰 요청 마감 | 없음 |
| **토 09:00** | 토 10:00 팀장 2차 PR | ⏰ 1시간 뒤 재리뷰 요청 마감 | 테크리더 |
| 일 20:00 | — | ⏰ 오늘 23:59 main 머지 마감 | 없음 |
| **일 23:00** | 일 23:59 팀장 머지 | ⏰ 1시간 뒤 main 머지 마감 | 테크리더 |

마감 1시간 전(수·토·일)에 **아직 리뷰가 하나도 없는 `develop` PR** 이 있으면 그 PR 마다 따로
`⏰ 1시간 뒤 … — 아직 리뷰가 없습니다` 가 붙고, **작성자와 리뷰어를 같이 부릅니다.**
멘토 리뷰 PR(`base=main`)은 이 독촉 대상이 아닙니다.

> **멘토 차례인 지점(목 22:00 리뷰 · 일 10:00 approve)에는 알림이 없습니다.** 시각이
> 확정된 것도 아니고 재촉할 일도 아닙니다. 대신 **멘토가 코멘트를 남기는 순간**
> 위 1번의 이벤트 알림이 테크리더까지 부릅니다.

## 멘션 대상은 어디서 오나

저장소 시크릿 **`DISCORD_MEMBERS`** 입니다. 깃허브 로그인 → 디스코드 사용자 ID 매핑과
테크리더 목록이 든 JSON 한 덩어리입니다. 형식은 `.github/discord-members.example.json`.

**저장소에 파일로 두지 않습니다.** 그 파일 하나로 "깃허브 계정 = 디스코드 계정 = 실명"이
연결되기 때문입니다. 디스코드 사용자 ID 자체는 서버에 있는 누구나 볼 수 있는 공개
식별자지만, 셋이 한 줄에 묶인 목록이 저장소 이력에 남는 건 다른 문제입니다.

### 사람이 들어오거나 나갈 때

```bash
# 1. 지금 값을 받아올 수는 없다(시크릿은 읽기 불가). 로컬 사본을 고친다
#    사본 위치: _local/설정/discord-members.json  (저장소에 커밋되지 않음)
# 2. 고친 뒤 통째로 다시 올린다
gh secret set DISCORD_MEMBERS < _local/설정/discord-members.json
```

> ⚠️ **시크릿은 값을 다시 읽을 수 없습니다.** 로컬 사본을 잃어버리면 처음부터 다시
> 만들어야 합니다. 사본이 `_local/설정/` 에 있는지 확인하세요.
>
> 디스코드 ID 얻는 법: 사용자 설정 → 고급 → 개발자 모드 켜기 → 멤버 우클릭 →
> "사용자 ID 복사하기"

로컬에서 손으로 돌려볼 때는 환경변수 `DISCORD_MEMBERS_PATH` 로 파일을 가리켜도 됩니다.

### 매핑이 없거나 깨졌을 때

**알림은 그대로 나가고 멘션만 빠집니다.** 멘션 하나 때문에 알림 전체를 못 보내는 게
더 나쁩니다.

| 상황 | 결과 |
|---|---|
| 시크릿이 아예 없음 | 멘션 없이 `` `로그인` `` 평문. Actions 로그에 notice |
| JSON 이 깨짐 | 같음. 로그에 warning (줄·열 위치만, **값은 출력하지 않음**) |
| 매핑에 없는 사람 | 그 사람만 `` `로그인` `` 평문. 나머지는 정상 멘션 |

> 멘션은 **content 에 넣어야 울립니다.** embed 안의 `<@id>` 는 링크로 보이기만 하고
> 알림이 가지 않습니다. 문구를 고칠 때 주의하세요.

## 웹훅

시크릿 이름은 **`DISCORD_WEBHOOK_TEAM`** 입니다. 운영진 공용 `DISCORD_WEBHOOK` 과
일부러 분리했습니다.

운영진 `DISCORD_WEBHOOK` 이 어느 채널을 가리키는지 우리는 알 수 없습니다(시크릿 값은
읽을 수 없습니다). CODEOWNERS 메모에 "Discord 채널 구조(학교별 5채널 vs 팀별)가
미확정" 이라 적혀 있어서, 그게 학교 공용 채널이면 우리 `develop` PR 알림이 다른 팀에까지
쏟아집니다. 운영진 알림은 주 1회라 티가 안 나지만 우리 건 주당 10건이 넘습니다.

**시크릿이 등록돼 있지 않으면 아무것도 보내지 않고 조용히 끝납니다.** 다른 웹훅을
기본값으로 대신 쓰지 않습니다. CI 는 실패하지 않습니다.

## 손으로 돌려보기

```bash
# 시간 기반 알림 — 특정 시각인 것처럼 굴려본다
GITHUB_TOKEN=$(gh auth token) GITHUB_REPOSITORY=kakaotechcampus-4/ktc4-kyungpook-6 \
  python3 .github/scripts/remind_discord.py --dry-run --now '2026-10-07T17:30+09:00'

# 이벤트 알림 — 이벤트 payload 파일을 만들어 넣는다
GITHUB_EVENT_PATH=event.json GITHUB_EVENT_NAME=pull_request \
  python3 .github/scripts/pr_event_notify.py --dry-run
```

`--dry-run` 은 디스코드로 보내지 않고 payload 만 출력합니다.
`remind-discord-team.yml` 은 Actions 탭에서 `workflow_dispatch` 로 수동 실행할 수도 있습니다.

## 운영진 보호 파일

`assign-mentor.yml` · `notify-discord.yml` · `convention-check.yml` 3개는 CODEOWNERS 가
운영진 소유로 잠가 둔 파일입니다. **건드리지 않습니다.** 여기 있는 건 전부 새로 추가한
파일이고, CODEOWNERS 는 `.github/workflows/` 에 팀 자체 워크플로를 새로 추가하는 것을
명시적으로 허용합니다.
