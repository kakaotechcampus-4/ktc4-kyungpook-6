# 도메인 용어집

같은 개념을 팀 전체(Front / Back / AI)가 같은 말로 부르기 위한 문서입니다.

실제로 용어를 코드에 써야 하는 시점에, 팀이 논의해서 확정한 뒤 이 문서에 먼저 기술합니다.

> 아래 "조사(Job/Task/Signal/Verification)" 관련 용어는 DB 스키마 작업 중에 초안으로 먼저
> 정하고 코드에 반영했습니다 — 순서가 원래 의도(용어 먼저 확정 → 코드 반영)와 반대로 됐습니다.
> PR 리뷰 때 팀원들 확인 받고 필요하면 수정할 예정이니, 리뷰 시 이 표를 꼭 봐주세요.

| 용어 | 정의 | 코드 | 화면 라벨 | 쓰지 않을 말 |
|---|---|---|---|---|
| Job 상태 (대기) | 아직 시작 안 한 Job | `JobStatus.PENDING` | 대기중 | |
| Job 상태 (진행중) | 조사가 진행 중인 Job | `JobStatus.IN_PROGRESS` | 진행중 | |
| Job 상태 (완료) | 조사가 정상 종료된 Job | `JobStatus.DONE` | 완료 | |
| Job 상태 (실패) | 조사 도중 오류로 중단된 Job | `JobStatus.FAILED` | 실패 | |
| Task 분류 (심각) | 담당자가 최우선으로 확인해야 할 Task | `TaskClassification.PRIORITY_CHECK` | 우선확인 | |
| Task 분류 (경미) | 추가로 확인이 권장되는 Task | `TaskClassification.ADDITIONAL_CHECK` | 추가확인 | |
| Task 분류 (없음) | 변화가 감지되지 않은 Task | `TaskClassification.NO_CHANGE` | 변화없음 | |
| Signal 유형 (심각) | 우선 검토가 필요한 이상 징후 | `SignalType.SIGNAL_HIGH` | 우선검토필요 | |
| Signal 유형 (경미) | 추가 검토가 권장되는 이상 징후 | `SignalType.SIGNAL_LOW` | 추가검토권장 | |
| Signal 유형 (없음) | 변화 근거가 부족한 상태 | `SignalType.SIGNAL_NONE` | 변화근거부족 | |
| 확인 결과 (확인됨) | 담당자가 이상 없음/있음을 실제로 확인함 | `VerificationResult.CONFIRMED` | 확인됨 | |
| 확인 결과 (해당없음) | 확인 대상 자체가 아니었음 | `VerificationResult.NOT_APPLICABLE` | 해당없음 | |
| 확인 결과 (보류) | 아직 확인하지 못함 | `VerificationResult.PENDING` | 보류 | |
| 확인 조치 (정보수정) | 가게 정보를 수정함 | `VerificationAction.UPDATE_INFO` | 정보수정 | |
| 확인 조치 (상태변경) | 영업 상태를 변경함 | `VerificationAction.CHANGE_STATUS` | 상태변경 | |
| 확인 조치 (조치없음) | 아무 조치도 취하지 않음 | `VerificationAction.NO_ACTION` | 조치없음 | |
| 국세청 조회 결과 (확인됨) | 국세청에서 사업자 상태를 확인함 | `NtsLookupResult.CONFIRMED` | 확인됨 | |
| 국세청 조회 결과 (확인안됨) | 조회했지만 응답이 없거나 해석하지 못함 — 다시 조회하면 확인될 수 있음 | `NtsLookupResult.UNCONFIRMED` | 확인안됨 | 실패 |
| 국세청 조회 결과 (번호없음) | 사업자번호가 없거나 형식이 틀려 조회하지 않음 | `NtsLookupResult.NO_BIZ_NO` | 번호없음 | |
| 사업자 상태 (계속) | 국세청 기준 계속사업자 (`b_stt_cd` 01) | `BusinessState.ACTIVE` | 계속사업자 | 영업중 |
| 사업자 상태 (휴업) | 국세청 기준 휴업자 (02) | `BusinessState.SUSPENDED` | 휴업자 | |
| 사업자 상태 (폐업) | 국세청 기준 폐업자 (03) | `BusinessState.CLOSED` | 폐업자 | |
| 사업자 상태 (미등록) | 국세청에 등록되지 않은 번호 | `BusinessState.NOT_REGISTERED` | 미등록 | |
| 상태 비교 (일치) | 우리 DB 상태와 국세청 상태가 같음 | `StatusComparison.MATCH` | 일치 | |
| 상태 비교 (불일치) | 두 상태가 다름. `우리상태_BUT_국세청상태` 형태 | `StatusComparison.OPEN_BUT_CLOSED` 등 | 불일치 | |
| 상태 비교 (미등록) | 국세청에 없는 번호라 맞춰볼 대상이 없음 | `StatusComparison.NTS_NOT_REGISTERED` | 미등록 | 불일치 |
| 상태 비교 (비교불가) | 우리 상태가 미확인이거나 국세청을 확인하지 못함 | `StatusComparison.NOT_COMPARABLE` | 비교불가 | 일치 |
| 조사 대상 | 우리 상태와 국세청 상태가 달라 AI 가 확인해야 하는 가게 | `StoreCheckResponse.statusMismatch = true` | 조사대상 | |
| 데이터 수정 대상 | 사업자번호가 없거나 국세청에 없어 담당자가 고쳐야 하는 가게 | `StoreCheckResponse.dataProblem = true` | 수정필요 | 조사대상 |
| 국세청 확인 시각 | 그 가게의 국세청 상태를 마지막으로 확인한 시각 | `StoreCheckResponse.ntsCheckedAt` | 국세청 확인일 | 확인일 |
| 담당자 확인 시각 | 담당자가 가게 정보를 직접 확인한 시각 | `Store.lastCheckedAt` | 확인일 | |

## 국세청 대조 용어 보충

**"확인안됨"과 "번호없음"을 나누는 이유**는 담당자가 할 일이 다르기 때문입니다.

| 값 | 원인 | 할 일 |
| :--- | :--- | :--- |
| `UNCONFIRMED` | 국세청 호출 실패·응답 누락 | 기다리면 다음 배치에서 확인됨 |
| `NO_BIZ_NO` | 우리 DB 에 번호가 없거나 형식이 틀림 | **번호를 찾아 넣어야 함** |

**"불일치"와 "미등록"도 나눕니다.** 불일치는 가게가 정말 폐업했는지 확인할 일(AI 조사)이고,
미등록은 우리 번호가 틀렸을 가능성(담당자 수정)이라 대응이 다릅니다.
`statusMismatch` 에 미등록을 포함하면 번호가 틀린 가게를 조사해 엉뚱한 결과가 나옵니다.

**시각이 두 개인 점에 주의하세요.** `ntsCheckedAt` 은 배치가 국세청을 확인한 시각이고,
`Store.lastCheckedAt` 은 담당자가 가게를 직접 확인한 시각입니다. 화면 라벨을 붙일 때 구분이 필요합니다.
