# Jira 사용 가이드

이슈(티켓)는 깃허브 이슈 말고 **Jira**로 관리.

---

## 스프린트

- **주기: 1주.** 매주 그 주에 할 일을 티켓으로 만들어서 스프린트에 담기.

## 티켓

- **제목 형식**: `[파트] 설명` — 예: `[Back] 가게 조회 API 구축`, `[AI] 상호명 반환 함수 개발`
- 파트는 `Front` / `Back` / `AI` 중 하나
- **필수로 채울 항목**: 담당자, 기한(마감일).

## 브랜치

- 티켓 화면에서 Jira의 **"브랜치 생성"** 기능을 사용해서 만들기. 자동 생성되는 브랜치 명으로 진행.
- 생성되는 패턴: `PROMPT-{티켓번호}-{파트}-{설명}` (예: `PROMPT-35-Back-컨밴션-문서화`)

## 상태 (4단계, 자동 전환)

**상태는 기분이 아니라 깃허브에 남은 사실로 정한다.** 각 상태는 깃허브에서 눈으로 확인할 수 있는
신호 하나에 대응한다. "거의 다 했는데 PR은 안 올렸다"는 **진행 중**이고, "PR 올렸는데 리뷰가 안
붙었다"도 **검토 중**이다.

| 상태 | 깃허브에서 보이는 신호 | 누가 옮기나 |
|---|---|---|
| 해야 할 일 | 아직 브랜치가 없다 | — (티켓 만들면 여기) |
| 진행 중 | **브랜치가 있다** (`PROMPT-{번호}-...`) | 자동 |
| 검토 중 | **PR 이 열려 있다** (→`develop`) | 자동 |
| 완료 | **PR 이 머지됐다** | 자동 |

**2026-10-01 부터 Jira 자동화가 옮긴다.** 카드를 직접 드래그하지 않아도 된다. 자동으로 안
옮겨진 것만 손으로 옮기면 된다.

### 왜 자동으로 바꿨나

원래는 "머지한 사람이 그 자리에서 티켓도 옮긴다"로 정했다. 그런데도 **2026-09-30 에 PR 3건이
머지됐는데 티켓은 며칠 동안 `진행 중`에 남아 있었다.** 사람이 기억해야 하는 일로 두면 바쁠 때
가장 먼저 빠진다.

확인해 보니 자동화 흐름이 하나(`브랜치 → 진행 중`)만 있었고 PR 쪽 둘이 없었다. 그래서 티켓이
`진행 중`까지만 가고 멈춰 있었던 것이다. 2026-10-01 에 빠진 둘을 채웠다.

### 상태명을 길게 바꾸지 않은 이유

`진행 중 · 브랜치` 처럼 전환 조건을 상태명에 붙이는 안을 검토했다(2026-10-01). 보드 컬럼이
좁아지고 이미 익숙한 이름이 바뀌는 비용이 더 크다고 보아 **이름은 그대로 두고 이 문서를
자세히 적는 쪽**으로 정했다. 헷갈리면 위 표의 "깃허브에서 보이는 신호"만 보면 된다.

## 자동 전환 (Jira Automation) — 켜져 있다

흐름 세 개가 돌고 있다. 프로젝트 설정 → 자동화에서 볼 수 있다.

| 흐름 이름 | 트리거 | 이슈 상태 |
|---|---|---|
| 브랜치를 만들면 → 이슈를 진행 중으로 이동 | 브랜치 만들어짐 | **진행 중** |
| PR을 만들면 → 이슈를 검토 중으로 이동 | 풀리퀘스트 만들어짐 | **검토 중** |
| PR이 머지되면 → 이슈를 완료로 이동 | 풀리퀘스트 병합됨 | **완료** |

**브랜치 이름에서 이슈 키를 찾는다.** 위 브랜치 이름 규칙(`PROMPT-{번호}-...`)을 따르면 자동으로
맞는다. 키가 없으면 아무 일도 하지 않는다 — `develop` → `main` PR 은 키가 없어서 엉뚱한 이슈를
건드리지 않는다.

### 설정이 저장소에 없는 이유

흐름은 Jira 안에만 있다. 규칙 편집 API 가 API 토큰으로는 닫혀 있어서(전부 404) 코드로 만들 수
없었고 브라우저로 직접 만들었다. 그래서 **무엇이 왜 켜져 있는지는 이 문서가 유일한 기록**이다.

### 안 움직일 때

**프로젝트 설정 → 자동화 → 감사 로그(Audit log)** 에 실행 기록과 실패 이유가 남는다. 세 흐름이
모두 **사용(Enabled)** 상태인지도 같은 화면에서 확인한다.
