# Jira 사용 가이드

이슈(티켓)는 깃허브 이슈 말고 **Jira**로 관리.

---

## 스프린트

- **주기: 1주.** 매주 그 주에 할 일을 티켓으로 만들어서 스프린트에 담기.

## 티켓

- **제목 형식**: `[파트] 설명` — 예: `[Back] 가게 조회 API 구축`, `[AI] 상호명 반환 함수 개발`
- 파트는 `Front` / `Back` / `AI` 중 하나
- **필수로 채울 항목**: 담당자, 기한(마감일).

## 브랜치

- 티켓 화면에서 Jira의 **"브랜치 생성"** 기능을 사용해서 만들기. 자동 생성되는 브랜치 명으로 진행.
- 생성되는 패턴: `PROMPT-{티켓번호}-{파트}-{설명}` (예: `PROMPT-35-Back-컨밴션-문서화`)

## 상태 (4단계, 현재는 수동 전환)

| 상태 | 의미 | 옮기는 시점 |
|---|---|---|
| 해야 할 일 | 아직 시작 안 함 | 티켓 생성 직후 |
| 진행 중 | 작업 중 | 브랜치 만들고 작업 시작할 때 |
| 검토 중 | 리뷰 대기 | 개인 PR(→develop)을 올렸을 때 |
| 완료 | 끝남 | 같은 파트 팀원이 리뷰 후 머지했을 때 |

지금은 **카드를 직접 드래그해서** 옮기기.

## 자동 전환 설정 방법 (Jira Automation)

깃허브 연동은 되어 있어서, 브랜치/PR 이벤트로 상태를 자동 전환할 수 있다고 하네요. 설정해놓으면 편리할 듯 합니다. **Jira 프로젝트 관리 권한이 있는 사람이** 아래대로 설정하면 됩니다.

1. Jira 프로젝트 → **프로젝트 설정** → **Automation**(자동화) 이동
2. **규칙 만들기(Create rule)** 클릭
3. **템플릿 라이브러리**에서 "개발(Development)" 카테고리 검색 → 아래 3개를 각각 규칙으로 추가:

| When (트리거) | Then (액션) |
|---|---|
| 브랜치 생성됨 (Branch created) | 이슈를 **진행 중**으로 전환 |
| PR 생성됨 (Pull request created) | 이슈를 **검토 중**으로 전환 |
| PR 머지됨 (Pull request merged) | 이슈를 **완료**로 전환 |

4. 각 규칙의 "Then" 액션에서 전환할 상태명을 정확히 우리 보드 컬럼 이름(해야 할 일/진행 중/검토 중/완료)과 똑같이 선택 — 이름이 다르면 전환 X.

이거 설정하면 위 "옮기는 시점" 티켓은 생성 제외 자동으로 처리된다고 하네요.
