# 백엔드 연동 — 설계와 현황

티켓 미정(작성 시점 2026-09-22) · 백엔드 `GET /api/stores/nts-checks`는 PR #32 기준

## 범위

AI 프로세스와 백엔드가 **HTTP로 주고받는 구간**만 다룬다. 조사 로직 자체
(`src/biz_number/`)나 결과를 DB에 어떻게 반영할지는 여기서 다루지 않는다.

## 두 방향을 섞지 않는다

"연동"이라고 부르지만 방향이 둘이고, 필요한 것이 다르다.

| 방향 | 누가 부르나 | 필요한 것 | 우리 코드 |
|---|---|---|---|
| 조사 자료 가져오기 | **AI → 백엔드** | HTTP 클라이언트 | `src/backend_client/` |
| 조사 시켜서 결과 받기 | **백엔드 → AI** | HTTP 서버 | `src/server/` |

지금 당장 필요한 건 위쪽뿐이다. 아래쪽은 조사를 실제로 돌릴 때 필요해지므로 **골격만**
만들어 두고 엔드포인트를 하나씩 붙인다.

한 모듈에 합치지 않은 이유는 **장애 지점과 테스트 방법이 다르기** 때문이다. 부르는 쪽은
백엔드가 죽었을 때를 다뤄야 하고, 불리는 쪽은 잘못된 요청이 왔을 때를 다뤄야 한다.

## 무엇을 가져오는가

`GET /api/stores/nts-checks` 하나다. 이 API는 **국세청을 직접 부르지 않고** 새벽 배치가
저장해 둔 기록을 읽는다. 그래서 외부 API 장애나 호출 한도와 무관하게 응답한다.

필터를 반드시 지정한다.

| 필터 | 대상 | 대응 주체 |
|---|---|---|
| `STATUS_MISMATCH` | 우리 상태와 국세청 상태가 다른 가게 | **AI 조사** |
| `DATA_PROBLEM` | 사업자번호가 없거나 틀린 가게 | **사람이 데이터 수정** |

**`DATA_PROBLEM`을 조사에 넘기면 안 된다.** 번호가 틀린 채로 조회하면 엉뚱한 가게를 보게
된다. `src/server/main.py`의 `/investigation-targets`가 `STATUS_MISMATCH`를 박아 두는 이유다.

`GET /api/stores`도 클라이언트에 넣어 뒀지만 화면용이라 국세청 정보가 없다. 연결 확인
(`/backend-health`)에만 쓴다.

## 반대 방향 — 백엔드가 AI를 부르는 자리

`POST /investigations` 가 그 자리다. 가게 목록을 받아 조사 결과를 돌려준다.

**조사 로직 자체는 여기 없다.** `src/investigation/protocol.py` 의 `Investigator` 를
구현해 `get_investigator()` 에 끼우면 된다.

**여기서 말하는 조사는 에이전트의 1차 조사다.** 아직 아무도 시작하지 않았다.
사업자등록번호 채우기(`src/biz_number/`, PROMPT-69)는 **다른 흐름이다** — 그쪽은
백엔드가 만들 사전 로직을 받아 별도 엔드포인트로 오게 될 예정이라, 이 자리에
꽂히는 것이 아니다. 처음에는 두 흐름을 하나로 보고 설계했다가 리뷰에서 바로잡았다.

그래서 이 티켓에서는 **경계만 고정하고 구현은 뒤로 미룬다.** 구현이 없는 동안
기본 `UnavailableInvestigator` 가 `503` 을 만든다 — 아직 못 한다는 사실을 200 으로
감추지 않는다.

**판정 결과를 담을 필드는 아직 없다.** 회의에서 조사 흐름이 정리되는 중이다 —
1차 조사(국세청 대조)는 백엔드 배치가 이미 하고, 2차 조사(웹서치)와 사업자번호
채우기는 서로 다른 흐름이다. 무엇을 돌려줄지 확정되면 그때 필드를 더한다.

지금 추측해서 넣으면 백엔드가 저장하는 `Task`(분류·수정안)·`Signal`(근거·신뢰도)과
어긋난 채로 굳는다. **빼는 것이 더하는 것보다 안전해서**, 어떤 조사든 공통인
`storeId`·`evidences`·`failure` 만 남겼다.

두 가지 규칙을 계약에 박아 뒀다.

- **한 건이 실패해도 결과에서 빼지 않는다.** `StoreFinding.failure` 를 채워 돌려준다.
  요청 수와 응답 수가 달라지면 부르는 쪽이 무엇이 빠졌는지 알 수 없다 — 국세청 배치에서
  같은 문제로 멘토 지적을 받았다(6주차 Q4).
- **근거(`Evidence`)를 함께 돌려준다.** 담당자가 전화로 확인하기 전에 "왜 그렇게 판단했는지"를
  읽어야 한다. 값만 주면 사람이 검증할 수 없다.

## 손으로 옮긴 타입이 어긋나는 문제를 테스트로 막는다

`src/backend_client/models.py`의 enum·필드는 전부 백엔드 Java 정의를 손으로 옮긴 것이다.
**이 팀은 같은 문제로 두 번 데였다** — 5주차에 가게 상태(`SUSPENDED`/`UNKNOWN`이 화면에서
빈 칸), 6주차에 Task 분류(`TASK_HIGH` ↔ `PRIORITY_CHECK`). 둘 다 멘토 리뷰에서 지적받았다.

멘토가 준 처방은 "백엔드가 컨트롤러 스텁을 먼저 머지하고, 프론트는 OpenAPI에서 타입을
생성한다"였다. 파이썬에도 생성기가 있지만 지금 단계에서 도입하면 **생성 시점에 백엔드가 떠
있어야** 하고, 배치·조사 코드까지 생성 타입에 묶인다.

그래서 한 단계 낮은 장치를 뒀다 — **`tests/backend_client/test_contract.py`가 백엔드 Java
파일을 직접 읽어 enum 값을 대조한다.** 같은 리포에 백엔드 소스가 있어서 가능한 방식이다.
백엔드가 값을 바꾸면 AI 테스트가 깨진다.

```
백엔드: ['CONFIRMED', 'UNCONFIRMED', 'NO_BIZ_NO']
파이썬: ['CONFIRMED', 'UNCONFIRMED', 'NO_BIZNO']      ← 이렇게 잡힌다
```

대조 대상은 `StoreStatus` · `StatusComparison` · `NtsLookupResult` · `BusinessState` 4개다.
**필드 이름까지는 대조하지 않는다.** 그건 OpenAPI 스펙을 봐야 하고, 백엔드를 띄워야 한다.
남은 구멍이다.

## 실행

```bash
# ai/ 에서
uv sync
cp .env.example .env          # BACKEND_BASE_URL 확인
uv run uvicorn src.server.main:app --reload --port 8000

curl localhost:8000/health              # AI 프로세스만 확인 (백엔드 안 봄)
curl localhost:8000/backend-health      # 백엔드에 닿는지
curl 'localhost:8000/investigation-targets?limit=5'
```

`BACKEND_BASE_URL`은 docker compose로 띄우면 서비스명(`http://backend:8080`)이 된다.
기본값은 `http://localhost:8080`이다.

## 실제 백엔드와 붙여본 결과 (2026-09-23)

`GET /api/stores/nts-checks`는 PR #32에만 있어 develop 기준으로는 띄울 수 없다.
그래서 **#32 브랜치를 워크트리로 받아 docker compose로 백엔드+DB를 띄우고** 확인했다.
로컬에 Gradle wrapper가 없어 `./gradlew`로는 못 띄우고, Dockerfile이 `gradle:8-jdk21`
이미지를 쓰기 때문에 이 경로만 가능했다.

검증용 가게 1건(내부 `OPEN` / 국세청 `CLOSED`)을 DB에 넣고 확인한 것:

| 확인 | 결과 |
|---|---|
| 응답 필드 17개가 우리 모델과 일치 | ✅ 이름·타입 모두 맞음 |
| `statusComparison` = `OPEN_BUT_CLOSED`, `statusMismatch` = true | ✅ |
| `ntsClosedAt`(date) · `ntsCheckedAt`(datetime) 파싱 | ✅ |
| `filter=DATA_PROBLEM` 이 조사 대상에서 빠짐 | ✅ 0건 |
| `limit=999` → 422 (백엔드에 가기 전에 막힘) | ✅ |
| 백엔드를 내렸을 때 `/health` | ✅ 200 유지 (AI 프로세스는 살아 있음) |
| 백엔드를 내렸을 때 `/backend-health` | ✅ 503 |
| 백엔드를 내렸을 때 `/investigation-targets` | ✅ 502 + 서버 로그 기록 |

**남은 것**: #32가 develop에 머지되면 계약 테스트 2건(skip 중)이 자동으로 켜지므로,
그때 한 번 더 돌려 확인한다.

## 아직 안 한 것
- **조사 로직을 붙이지 않았다.** `POST /investigations` 는 자리만 있고, 에이전트 1차 조사 구현은 아직 시작 전이다.
  `/investigation-targets` 도 백엔드 응답을 그대로 돌려주기만 한다.
- AI 서비스를 `docker-compose.yml`에 넣지 않았다 (인프라 파트와 협의 필요).
- 인증이 없다. 지금은 로컬에서만 부른다는 전제다.
