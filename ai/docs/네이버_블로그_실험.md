# 네이버 블로그 검색 실험 — 브라우저 vs 검색 API

갱신 2026-10-05 · 상태: 로컬 실험 (운영 미반영)

## 왜 했나

2차 조사(`2차_조사.md`)의 구글 검색 그라운딩은 네이버 블로그를 출처로 거의 가져오지 못한다(간이 DB 60곳에서
0건). 네이버 robots.txt 가 `Google-Extended` 를 막아 두었기 때문으로 보인다. 그런데 동네 가게 정보는 네이버
블로그에 가장 많다. 그래서 네이버 블로그를 직접 보게 하면 관측이 늘어나는지 쟀다.

1. 먼저 브라우저로 블로그를 긁는 방식을 만들었다
2. 그 결과가 검색 API 결과와 같다면 API 가 더 간단하니, API 로도 같은 실험을 했다

> **약관** — 운영에는 넣지 않는다. 네이버 robots.txt 는 AI 학습·RAG 봇 접근을 금지하고, 2026-09-07 개정
> 검색 API 약관은 "검색 결과 제공 목적으로만" 이용하게 하며 AI 입력·저장을 금지한다(기사 기준, 원문 미확인).
> NAVER API HUB 쪽 약관은 따로 확인하지 않았다. 결과 시트는 `eval/fixtures/`(커밋 금지)에만 쓴다.

## 비교한 방식

| 이름 | 스크립트 | 검색 | 본문 | 근거 검증 |
|---|---|---|---|---|
| 브라우저 `n1` | `eval/naver_browse.py` | Playwright 로 모바일 블로그 검색 화면 | 글을 열어 읽음 | 근거 문장이 **글 본문**에 그대로 있어야 함 |
| API `a1` | `eval/naver_api.py` | 블로그 검색 API (모델이 정렬 선택) | 안 읽음 | 근거 문장이 **검색 결과의 제목·요약**에 그대로 있어야 함 |
| API `a2` | 〃 | 최신순·정확도순을 합쳐 최신 글부터 + 항목별 최신 글만 판정 | 안 읽음 | 〃 |
| API `a3` | 〃 (`rescore`) | `a2` 관측을 다시 검색하지 않고 확인일 규칙만 적용 | 안 읽음 | 〃 |

공통: Gemini 2.5 Flash 가 도구를 최대 8번 부르고 `항목 | 값 | 근거 문장 | URL` 로 답한다. 판정은 운영과 같은
`classify()`. 대상은 간이 DB v9 에서 **그라운딩 근거가 0건이었던 37곳**(답안 기준 폐업 24 · 영업 13).

## 검색 API 가 주는 것

개발자센터 검색 API 는 2026-07-31 로 신규 발급이 끝나 **NCP NAVER API HUB** 로 옮겨 갔다.

- 주소 `https://naverapihub.apigw.ntruss.com/search/v1/blog` (카페는 `/search/v1/cafearticle`)
- 헤더 `X-NCP-APIGW-API-KEY-ID` · `X-NCP-APIGW-API-KEY` (`.env` 의 `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET`)
- 응답 형식은 예전 개발자센터 API 와 같다. 네이버 밖 블로그(티스토리 등)도 섞여 온다

| | 블로그 | 카페 |
|---|---|---|
| 필드 | 제목, 링크, 요약, 블로거, **작성일**(`postdate`) | 제목, 링크, 요약, 카페 이름 |
| 요약 길이 | 약 110~130자 | 약 120~140자 |
| 본문 전체 | 없음 | 없음 |

**"요약"은 생성된 요약이 아니라 검색엔진 발췌(스니펫)다.** 본문에서 검색어가 나온 부분을 원문 그대로 잘라
오고, 일치한 단어를 `<b>` 로 감싸며, 정해진 길이에서 `...` 로 끊긴다. 검색어가 달라지면 같은 글에서도 다른
부분이 발췌된다.

- 장점: 원문이라 "근거 문장이 결과에 그대로 있어야 인정" 검증이 그대로 동작한다
- 한계: 120자 안에 안 걸린 정보(글 뒤쪽의 폐업 언급, 잘린 번호·주소)는 보이지 않는다
- 카페는 작성일이 없어 아래 날짜 규칙을 쓸 수 없다

## 결과

| | 브라우저 n1 | API a1 | API a2 | API a3 (확인일 2025-10-05) |
|---|---|---|---|---|
| 근거를 찾은 가게 | 14 | 11 | 12 | 5 |
| 폐업 신호 | **3** | 1 | 1 | 1 |
| 우선확인 판정 | 12 | 9 | 9 | **4** |
| 근거 글 시점 | 대부분 2025~26 | 2019~23 많음 | 대부분 2025~26 | 2025-10 이후만 |
| 가게당 평균 | 23초 | 15초 | 16초 | – |

같은 확인일 규칙을 브라우저 n1 에 적용하면 우선확인 12 → 7 이고, **폐업 3곳(하누탕·우수분식·스윗문)은 모두
남는다** — 폐업 언급이 2025-11 이후 글에 있었다.

### 가게별로 갈린 곳

| 가게 | 브라우저 n1 | API |
|---|---|---|
| 하누탕 · 우수분식 | 폐업 확인 | 못 찾음 (폐업 언급이 요약에 안 걸림) |
| 돈뼈락 | 2025 글의 053 번호 | a1: 2019 글의 050 번호 → a2 날짜 규칙으로 2020 번호 → a3 에서 제외 |
| 감나무집 | 2026-09 글의 번호 | 요약에서 잘린 주소 "수성구 범어동 3층" 을 제안 |
| 에브리띵 | 같은 건물 팝업 매장을 같은 가게로 오인 | 2023 글뿐 → a3 에서 제외 |
| 스윗문 · 빠레뜨 · 디플랫 · 행컵 | 같은 결론 | 같은 결론 (디플랫·행컵은 a3 에서 오래된 글이라 제외) |

## 알게 된 것

1. **API 요약만으로는 폐업을 못 잡는다.** 폐업 문장은 본문에 있다. 폐업까지 보려면 본문을 열어야 한다
2. **전화·주소 불일치(2차 조사 주 목표)는 날짜만 다루면 API 로도 비슷하다.** 문제의 대부분이 옛날 글이었다
3. **옛날 글 자체가 아니라 "옛날 글 값 ≠ DB 값"이 오탐이다.** DB 가 더 최신인데 옛 값을 수정안으로 올린다
4. **블로그는 출처 도메인이 늘 하나라 `classify()` 의 "출처 수가 많은 값" 규칙이 동작하지 않는다.** 날짜가
   다른 값이 맞서면 아무거나 고른다 → 항목별 최신 글만 남겨야 한다(`latest_only`)
5. **모델에게 최신순을 고르게 두면 잘 안 고른다**(a1: 86번 중 30번). 검색 쪽에서 강제해야 한다
6. **실행마다 찾는 가게가 흔들린다**(a1 의 돈뼈락이 a2 에서 빠지고 천하무적·행림정이 새로 잡힘). 37곳
   규모에서 한두 곳 차이는 노이즈일 수 있다

## 날짜 규칙 — 담당자 확인일보다 최신인 글만

**출처 글의 작성일이 우리 DB 값을 마지막으로 확인한 날보다 나중일 때만 수정안을 올린다.** 그 전 글은 그 뒤에
사람이 본 DB 값이 더 믿을 만하므로 판정에서 뺀다. 고정 기간(예: 1년)보다 정확하고, 확인한 지 오래된 가게일수록
인정되는 글의 범위가 넓어진다.

- 기준 값은 **`Store.lastCheckedAt`**(담당자 확인 시각). 추가확인 90일 판정에 쓰는 그 값이다. 국세청 배치
  시각 `ntsCheckedAt` 은 사람이 값을 본 게 아니라 쓰지 않는다
- 판정 순서: 검증된 관측 → 확인일 이전·날짜 모름 제외(`mark_stale`) → 항목별 최신 글만(`latest_only`) → `classify()`

주의할 점:

- `lastCheckedAt` 이 비어 있는 가게(초기 데이터)는 원천 데이터 기준일, 그것도 없으면 기본 기간으로 대신한다.
  **DB 적재일을 쓰면 모든 글이 그보다 오래돼 전부 무시된다**
- 가게 단위 시각이라, 담당자가 확인할 때 전화·주소·상호를 다 봤다는 전제가 있다
- 작성일 ≠ 사실 시점일 수 있다(최근 글에 예전 방문기). 사람이 검토하는 수정안이라 허용한다
- 지금 AI 입력(`InvestigationTarget`)에는 `lastCheckedAt` 이 없다 → **백엔드 요청 후보**

## 남은 것

- **잘린 주소 거르기** — 번지가 없는 주소("수성구 범어동 3층")는 제안하지 않는 규칙. 날짜 규칙으로는 안 걸러진다
- **B안: API 검색 + 본문 열기** — 폐업 신호까지 보려면 필요. 검색은 API, 본문은 브라우저
- **다른 가게 오인** — 같은 건물·비슷한 이름(에브리띵 ↔ 에브리띵시즈닝). 동일 대상 확인이 필요
- **약관** — 운영 투입 여부는 멘토와 상의. API HUB 약관 원문 확인

## 돌려 보기

```bash
cd ai
# 브라우저 (설치된 크롬 사용)
uv run --with playwright python -m eval.naver_browse run --tag n1
# 검색 API (본문 없이 요약만). --checked-at 을 주면 그보다 이전 글은 판정에서 뺀다
uv run python -m eval.naver_api run --tag a2
uv run python -m eval.naver_api run --tag a4 --checked-at 2025-10-05
# 다시 검색하지 않고 판정 규칙만 다시 적용
uv run python -m eval.naver_api rescore --tag a3 --from a2 --checked-at 2025-10-05
uv run python -m eval.naver_api show --tag a3
```

결과 시트: `eval/fixtures/naver_browse_<tag>.csv`, `eval/fixtures/naver_api_<tag>.csv` (커밋 금지)
