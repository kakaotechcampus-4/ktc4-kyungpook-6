# 계약 대조

손으로 옮긴 타입은 조용히 어긋난다. 이 저장소에서 세 번 그랬다.

| 언제 | 무엇이 어긋났나 | 어떻게 드러났나 |
|---|---|---|
| 5주차 | 가게 상태 enum | 멘토 리뷰에서 지적 |
| 6주차 | Task 분류 enum | 멘토 리뷰에서 지적 |
| 9주차 | `failure` 의 **모양**(객체 ↔ `String`) | 머지 뒤 손으로 대조하다 발견 |

5·6주차 뒤에 `ai/tests/backend_client/test_contract.py` 를 만들어 **이름과 enum 값**은 자동으로 잡게 했다. 그런데 9주차 건은 그 테스트가 못 잡았다 — **이름은 맞고 모양이 달랐기** 때문이다. 그리고 그 칸은 테스트가 비교에서 빼 둔 칸이었다.

그래서 이 스킬은 **세 가지를 따로** 본다.

1. **있나** — AI 가 보내는 칸이 백엔드에 있는가
2. **모양이 같나** — 객체를 보내는데 `String` 으로 받고 있지 않은가
3. **누가 보고 있나** — 그 칸의 모양을 검사하는 테스트가 실제로 있는가. 없으면 사각지대다

## 쓰는 법

```bash
ai/.venv/bin/python .claude/skills/계약-대조/check_contract.py
ai/.venv/bin/python .claude/skills/계약-대조/check_contract.py --gen-test   # 사각지대용 테스트 뼈대
```

리포지토리 루트에서 돈다. 어긋난 칸이 있으면 **종료 코드 1** 이라 CI 에 걸 수 있다.
백엔드 소스가 없으면 그 쌍만 건너뛴다.

읽는 기호

| | 뜻 |
|---|---|
| `✓` | 양쪽에 있고 모양도 맞다 |
| `△` | 이름 비교에서 뺐고 **모양을 보는 곳도 없다** — 사각지대 |
| `✗` | 칸이 없거나 모양이 어긋났다 |

## 어떻게 보는가

**스키마가 아니라 실제 직렬화 결과를 본다.** `exclude=True` 인 칸(`observed`·`sourceCount`·`mapCheck`)은 스키마에는 남아 있지만 응답에는 안 나간다. 스키마를 보면 "백엔드에 칸이 없다" 는 거짓 보고가 난다.

**자바는 정규식으로 읽는다.** `record Result(...)` 같은 중첩 record 와 `private X y;` 엔티티 둘 다 읽는다. 기존 계약 테스트의 `java_enum_values`·`java_fields` 와 같은 방식이다.

`<>` 깊이를 세서 쉼표를 나눈다. `Map<String, String> proposedChanges` 를 그냥 `split(",")` 하면 두 토막으로 쪼개져 **"백엔드에 칸이 없습니다" 라는 거짓 보고**가 난다. 처음 짤 때 그렇게 틀렸다.

## 쌍을 추가할 때

`check_contract.py` 의 `PAIRS` 에 한 줄 넣는다.

```python
("AI 모델 이름", {샘플 만들 kwargs}, "도메인/부터/자바파일.java", "자바 쪽 record 이름")
```

자바 쪽 이름에 `None` 을 주면 `private X y;` 형태의 엔티티로 읽는다.

`kwargs` 는 **필수 칸만** 채우면 된다. 모양을 보려는 칸은 값을 넣어야 보인다 — `None` 이면 `null(모양 미정)` 로 나와서 객체인지 문자열인지 알 수 없다.

## 한계 — 알고 쓸 것

**프론트 층은 지금 대조할 수 없다.** `frontend/src/api/generated` 를 커밋하지 않아 정적으로 읽을 파일이 없다. 9주차 멘토 리뷰 🟢6(생성 코드 커밋, PROMPT-126)이 들어가야 `AI → BE → FE` 세 층이 다 이어진다. 지금은 `AI → BE` 두 층만 본다.

**`null` 로 오는 칸은 모양을 모른다.** 샘플에서 값을 채워야 객체/문자열이 갈린다. `PAIRS` 의 `kwargs` 에 넣어 주면 된다.

**정규식이라 자바 문법 전체를 이해하지 못한다.** 애너테이션이 붙은 record 구성요소나 여러 줄에 걸친 제네릭은 놓칠 수 있다. 놓치면 `✗ 칸이 없습니다` 로 **과하게** 보고하는 쪽으로 틀리니, 그 보고가 나오면 자바 파일을 직접 열어 확인한다.

**"칸이 없다" 가 곧 버그는 아니다.** 백엔드가 **일부러 안 받는** 칸이 있다(`AiInvestigationResponse` 주석의 `mapCheck`·`evidences`·`sourceCount`). 보고가 나오면 **그래서 무슨 일이 생기는지**까지 확인한다 — 그 값을 읽는 곳이 있는지, 없으면 지금 깨지는 건 없다. 한 겹만 보고 "값이 버려지고 있다" 고 적어 틀린 전례가 있다(`CLAUDE.md`).

## 테스트로 굳히기

사각지대를 찾았으면 `--gen-test` 로 뼈대를 받아 `ai/tests/backend_client/test_contract.py` 에 넣는다. 뼈대는 `TODO` 가 들어 있으니 채워야 한다.

**양쪽이 어긋나 있고 통일 방향이 아직 안 정해졌다면** `@pytest.mark.xfail(strict=True)` 로 둔다. `develop` 을 빨갛게 두지 않으면서 어긋남을 코드에 남긴다. `strict` 라서 양쪽을 맞추면 XPASS 로 실패하고, 맞춘 사람이 마커를 지우게 된다. `test_failure_모양이_양쪽에서_같다` 가 그 예다.

**테스트는 통일 방향을 먼저 정해 버리지 않게 짠다.** "AI 가 객체면 백엔드도 객체, AI 가 문자열이면 백엔드도 문자열" 처럼 **둘이 같은지만** 본다. 어느 쪽이 맞는지는 파트끼리 정할 일이다.
