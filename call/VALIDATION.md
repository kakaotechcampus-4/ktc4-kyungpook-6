- `python -m unittest discover -s tests -q`: **72개 중 71개 통과, 1개 건너뜀**, 실패 없음. 마지막 실행 3.969초.
- 이번 환경에는 FFmpeg 실행 파일이 없어 실제 변환 검사 1개를 건너뛰었습니다. 2026-11-01 검증에서는 실제 FFmpeg로 8kHz PCM → 필터 적용 16kHz PCM → 8kHz PCM 변환과 샘플레이트, 채널 수, 샘플 폭, 길이를 확인했습니다.
- 모의 외부 API로 Whisper multipart 업로드, ElevenLabs 모델/음성 요청과 캐시, LLM JSON 검증, Jev `noul` 판정 계약을 확인했습니다.
- 실제 프로세스/파이프/스레드를 사용해 재생 중 녹음이 계속되는지 확인했습니다. 전화 장치 대신 합성 PCM을 사용했습니다.
- FastAPI TestClient로 접수 202, 결과 조회, UUID 검증, 인증, 404/422, healthz, OpenAPI를 검사했습니다.
- 동시 SQLite 접수/claim, FIFO, 모뎀 중복 worker 잠금, 오류 이후 다음 통화, 재시작 복구, 큐 용량을 확인했습니다.
- 모의 통화로 인사와 전화용 변환이 발신보다 먼저 끝나는지, 연결 후 재생되는지, 16kHz 변환을 STT 전에 호출하는지, Jev 이후 재생이 중단되는지 확인했습니다.
- 추임새 유지 및 다음 발화에 한 번만 결합, 이전 질문의 지연된 답변 방지, 부분 답변을 보존한 종료, 모든 답변 수집 후 종료, 마무리 중 값 정정, 무응답/원격 종료/API 실패의 정리를 검사했습니다.
- 기존 모뎀 회귀 검사를 가져와 음성 모드, 오디오 이득 설정·복원, LTE 등록 대기, GPS 출력 복원, CLCC 판별, 연결 거절, 예외 시 연결 정리를 확인했습니다.
- Compose 설정은 `.env.example`을 지정한 구성으로 `docker compose config --quiet` 검증을 통과했습니다.
- OpenAPI 스키마를 `examples/openapi.json`에 생성했습니다.

검증에 사용한 pyserial 및 FFmpeg 실행 파일은 별도 작업 디렉터리에 설치했으며 결과 프로젝트에 포함하지 않았습니다. 배포 시 `requirements.txt`와 Linux FFmpeg를 설치하거나 제공한 Dockerfile을 사용합니다.

실제 EP06-E/SIM/통신망, 실제 수신자, 운영 API 키를 사용하는 통화는 실행하지 않았습니다. 따라서 펌웨어 호환성, 게이트웨이 응답, 음성 인식·의도 분류 정확도, 실통화 지연·에코는 현장 검증이 필요합니다. Docker daemon이 실행 중이지 않아 이미지 빌드와 컨테이너 실행은 검증하지 못했습니다. 테스트 시간은 실통화 응답 성능을 의미하지 않습니다.
