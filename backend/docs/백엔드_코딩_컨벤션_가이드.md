# 코딩 컨벤션

> 이 문서는 에이전트에게 코드 검토 시 참고용으로 제공하는 가이드로 활용하면 될 거 같습니다.

약어 표기 규칙은 네이버 코딩 컨벤션에서 가져왔고, 나머지(DTO 네이밍/Lombok/예외 처리/로깅)는 일반적인 Java/Spring Boot 베스트 프랙티스를 참고해 이 프로젝트용으로 정한 것입니다. 들여쓰기/줄바꿈 문자처럼 도구가 자동으로 처리하는 기본 스타일은 여기 안 다룹니다.

---

## 네이밍

- **약어도 카멜케이스로**: `getOpenApi()`, `parseUrl()` (❌ `getOpenAPI()`, `parseURL()`)
- **DTO는 `{도메인}Request` / `{도메인}Response`** (❌ `Dto` 접미사 안 붙임) — 이미 Javadoc/스웨거 가이드 예시에서 이 형식으로 쓰고 있음

## Lombok

- **Entity에 `@Data` 쓰지 않기** — 이유 두 가지: (1) 양방향 연관관계가 있으면 `toString()`/`equals()`가 서로를 참조하다 무한루프에 빠질 수 있음 (2) `equals()`/`hashCode()`가 모든 필드 기준으로 생성되는데, 엔티티는 영속화 전/후로 필드 값이 바뀌어서 `Set`/`Map`에 넣었을 때 조용히 깨질 수 있음
- 대신 `@Getter`만 쓰고, 필요한 setter만 명시적으로 추가 (또는 생성자/변경 메서드로 대체)

## 예외 처리

`ErrorCode` enum + `CustomException` + `@RestControllerAdvice` 조합 사용. 비즈니스 로직에서 예외 상황이면 `throw new CustomException(ErrorCode.XXX)`로 던지기 — try-catch로 감싸서 삼키지 않기.

패턴 예시 (실제 `ErrorCode` 목록/클래스명은 프로젝트 진행하며 채워나가면 됨):

```java
@Getter
@RequiredArgsConstructor
public enum ErrorCode {
    STORE_NOT_FOUND(HttpStatus.NOT_FOUND, "요청한 가게를 찾을 수 없습니다"),
    INVALID_REQUEST(HttpStatus.BAD_REQUEST, "잘못된 요청입니다");

    private final HttpStatus httpStatus;
    private final String message;
}

public class CustomException extends RuntimeException {
    @Getter
    private final ErrorCode errorCode;

    public CustomException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.errorCode = errorCode;
    }
}

public record ErrorResponse(
        @Schema(description = "에러 코드", example = "STORE_NOT_FOUND") String code,
        @Schema(description = "에러 메시지", example = "요청한 가게를 찾을 수 없습니다") String message
) {
    public static ErrorResponse of(ErrorCode errorCode) {
        return new ErrorResponse(errorCode.name(), errorCode.getMessage());
    }
}

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(CustomException.class)
    public ResponseEntity<ErrorResponse> handleCustomException(CustomException e) {
        ErrorCode errorCode = e.getErrorCode();
        log.warn("CustomException 발생: {}", errorCode, e);
        return ResponseEntity.status(errorCode.getHttpStatus())
                .body(ErrorResponse.of(errorCode));
    }
}
```

> `@RestControllerAdvice`가 예외를 "처리"해버리면 Spring이 자동으로 남기던 에러 로그가 더 이상 안 남습니다. 여기서 직접 로그를 남겨야 나중에 뭐가 실패했는지 서버 쪽에서 추적할 수 있습니다.

## 로깅

- SLF4J + Lombok `@Slf4j` 사용
- 파라미터 바인딩으로 로그 남기기: `log.info("가게 생성됨: {}", storeId)` (❌ 문자열 이어붙이기 `"가게 생성됨: " + storeId`)
- **비밀번호/토큰/API 키 등 민감정보는 로그에 남기지 않기**
- 레벨: `ERROR`(예외/실패) / `WARN`(예상 가능한 이상 상황) / `INFO`(주요 비즈니스 이벤트) / `DEBUG`(개발 중 상세 추적)
