# 코딩 컨벤션

> 이 문서는 에이전트에게 코드 검토 시 참고용으로 제공하는 가이드로 활용하면 될 거 같습니다.

약어 표기 규칙은 네이버 코딩 컨벤션에서 가져왔고, 나머지(DTO 네이밍/Lombok/예외 처리/로깅)는 일반적인 Java/Spring Boot 베스트 프랙티스를 참고해 이 프로젝트용으로 정한 것입니다. 들여쓰기/줄바꿈 문자처럼 도구가 자동으로 처리하는 기본 스타일은 여기 안 다룹니다.

---

## 네이밍

- **약어도 카멜케이스로**: `getOpenApi()`, `parseUrl()` (❌ `getOpenAPI()`, `parseURL()`)
- **DTO는 `{도메인}Request` / `{도메인}Response`** (❌ `Dto` 접미사 안 붙임) — 이미 Javadoc/스웨거 가이드 예시에서 이 형식으로 쓰고 있음

## Lombok

- **Entity에 `@Data` 쓰지 않기** — 이유 두 가지: (1) 양방향 연관관계가 있으면 `toString()`/`equals()`가 서로를 참조하다 무한루프에 빠질 수 있음 (2) `equals()`/`hashCode()`가 모든 필드 기준으로 생성되는데, 엔티티는 영속화 전/후로 필드 값이 바뀌어서 `Set`/`Map`에 넣었을 때 조용히 깨질 수 있음
- 대신 `@Getter`만 쓰고, 필요한 setter만 명시적으로 추가 (또는 생성자/변경 메서드로 대체)

## 예외 처리

`ErrorCode` enum + `CustomException` + `@RestControllerAdvice` 조합 사용. 비즈니스 로직에서 예외 상황이면 `throw new CustomException(ErrorCode.XXX)`로 던지기 — try-catch로 감싸서 삼키지 않기.

패턴 예시 (실제 `ErrorCode` 목록은 코드를 보세요 — 아래 `STORE_NOT_FOUND` 는 설명용입니다):

```java
@Getter
@RequiredArgsConstructor
public enum ErrorCode {
    STORE_NOT_FOUND(HttpStatus.NOT_FOUND, "요청한 가게를 찾을 수 없습니다"),
    INVALID_REQUEST(HttpStatus.BAD_REQUEST, "요청 값이 올바르지 않습니다");   // 실제 값. 이 파일은
                                                                       // 예시니 최신 문구는 코드를 보세요

    private final HttpStatus httpStatus;

    // RFC 9457 응답의 title. getMessage() 로 안 부르는 이유는 Throwable.getMessage() 와 읽는
    // 방식이 겹쳐서 헷갈리기 때문이다 — CustomException.getMessage() 가 이 title 값을 그대로
    // 반환하는데(자바 예외 메시지로 쓰기 위해), "ErrorCode.getMessage()"라는 이름은 그게
    // 응답 필드인지 예외 메시지인지 구분이 안 된다.
    private final String title;
}

// 서비스 어디선가
throw new CustomException(ErrorCode.STORE_NOT_FOUND);
```

여기까지는 `GlobalExceptionHandler`를 안 건드려도 됩니다 — **단, 비즈니스 예외(`CustomException`)일 때만입니다.**
프레임워크가 던지는 예외(404/405/415/5xx 등)에 새 상태코드 대응을 추가하려면 `GlobalExceptionHandler`의
`errorCodeFor()`를 고쳐야 합니다. 자세한 내용과 두 경로의 차이는 [에러_처리_가이드.md](../../docs/에러_처리_가이드.md) 참고.

> **응답 형태, 프론트가 읽는 법, 핸들러를 고칠 때의 주의사항은 [에러_처리_가이드.md](../../docs/에러_처리_가이드.md)를 보세요.**
> 특히 `@ExceptionHandler`를 새로 추가하면 앱이 기동하지 않을 수 있습니다.

## 로깅

- SLF4J + Lombok `@Slf4j` 사용
- 파라미터 바인딩으로 로그 남기기: `log.info("가게 생성됨: {}", storeId)` (❌ 문자열 이어붙이기 `"가게 생성됨: " + storeId`)
- **비밀번호/토큰/API 키 등 민감정보는 로그에 남기지 않기**
- 레벨: `ERROR`(예외/실패) / `WARN`(예상 가능한 이상 상황) / `INFO`(주요 비즈니스 이벤트) / `DEBUG`(개발 중 상세 추적)
